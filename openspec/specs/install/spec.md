## Purpose

The box is installed and reinstalled from the flake plus the secrets file plus the admin-held host key, with one command over Ethernet, so a disk swap or a corrupted install is a repeatable procedure rather than an afternoon.

## Requirements

### Requirement: One-command install over Ethernet
From the admin's machine, one documented command SHALL partition the target disk to the declared layout, install the configuration, and reboot the box into it, with the box connected by Ethernet and booted into a stock installer. The flake's hardware facts SHALL be authoritative; the installer SHALL NOT generate a hardware configuration.

#### Scenario: Fresh install
- **WHEN** the admin runs the documented install command against a box booted into the installer
- **THEN** the disk carries the declared partition and subvolume layout and the box reboots into the flake's configuration with no further prompts

#### Scenario: Install from macOS
- **WHEN** the install command is run from the admin's Mac with the configured Linux builder
- **THEN** the system closure is built on the builder and copied to the box; nothing is compiled on the box

### Requirement: Host identity is supplied at install, not generated
The SSH host key SHALL be generated by the admin before the first install, kept outside the repository, and placed under `/persist` by the install so that the box's identity, and therefore its ability to decrypt the secrets file, is the same on every install of this host.

#### Scenario: Reinstall decrypts without re-keying
- **WHEN** the box is reinstalled with the same host key
- **THEN** secrets decrypt on first boot with no change to the secrets file or its recipients, and existing SSH known-hosts entries stay valid

### Requirement: Reinstall and disk swap path
The documented procedure SHALL cover a reinstall on a new or wiped disk: run the install, then either restore `/data/saves`, `/data/es-de`, `/data/bios`, and `/data/home/player` from a verified off-site recovery or start with those protected roots empty. ROMs, scraped media, caches, and local snapshot history SHALL be reconstructed separately and SHALL NOT be described as recoverable from the off-site repository. Nothing on the old disk SHALL be required.

#### Scenario: Disk swap
- **WHEN** the disk is replaced and the install is run
- **THEN** the box boots with an empty, correctly laid out `/data` ready for the four protected roots to be restored and reconstructible content to be repopulated separately

#### Scenario: Disk swap uses off-site recovery
- **WHEN** the operator restores the off-site repository after a disk swap
- **THEN** only the four protected roots are expected from restic and ROMs, scraped media, caches, and local snapshot history are reconstructed separately

### Requirement: Post-install checklist
The repository SHALL document, readable from a fresh clone, the prerequisites (admin age key, host key, installer media with root SSH access enabled, Ethernet, Secure Boot off) and the checks to run after install: secrets decrypt, the WiFi profile is present, the root is ephemeral, and `admin` can log in. It SHALL state that pushing configuration changes to the installed box is not provided by this layer.

#### Scenario: Runbook is self-contained
- **WHEN** a reader with a fresh clone follows the install section of the README
- **THEN** every command and prerequisite is stated there or in files the README names; nothing depends on untracked notes
