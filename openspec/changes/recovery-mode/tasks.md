Every later task in this group adds its attributes under that block. Verify by evaluating the host configuration and asserting the declarations are unchanged in effect: the values task 2.1 lists
- [ ] 1.2 Define the clear-only helper as a `writeShellApplication` in a `let` binding in `modules/recovery/default.nix` and put it on `environment.systemPackages`; declare an internal, read-only option under `options.emubox` whose value is the helper's `${pkg}/bin/<name>` path, following `emubox.emulators.configDirs` in `modules/emulators`; and add a `security.sudo.extraRules` entry, built from that option, granting `player` exactly that one store path with `NOPASSWD` and nothing else (D5, D6). The helper takes no argument, ignores any it is given, and its whole body removes `/run/emubox/mode`, succeeding when the file is already absent. Verify by evaluating the host configuration and asserting: the option resolves to a store path under the helper's own derivation; the sudo rule names that same string, applies to `player` alone and adds no other command; `player` is still not in `wheel`; and no polkit rule grants `player` anything about the display manager. Prove the helper's shape by reading it - a body that can only remove that path - since a test can show it removed the flag, not that it could never write one
- [ ] 1.3 Add `systemd.tmpfiles.rules = [ "d /run/emubox 0755 root root -" ]`, the repository's first rule under `/run` (D9); verify by evaluating the host configuration and asserting the rendered tmpfiles rules contain that line and that no other rule declares `/run/emubox` with a different mode or owner
- [ ] 1.4 Define `emubox-mode` as a second `writeShellApplication` in the same `let` binding, with `systemd` in `runtimeInputs`, and put it on `environment.systemPackages` (D3, D8, D9). In this order, with nothing touched before a refusal, the script: refuses no argument, an unrecognised word, and anything after `kiosk` or `desktop`, with a usage message naming the two words and that exactly one is taken; refuses a non-root invocation with a message naming the route from the box's own desktop, `su - admin` and then `sudo`, not a bare `sudo`; refuses where the running system's automatic login is not enabled, saying that nothing there would read the mode - the observable is the `[Autologin]` section of `/etc/sddm.conf.d/00-nixos.conf`, present only where automatic login is enabled, and never a configured user name. Every refusal and every failure exits non-zero and names which mode is selected for the next automatic session as a result, by the session's own rule: `desktop` only when the flag holds exactly `desktop`, and `kiosk` in every other case - absent, empty, unreadable or unrecognised. Past the refusals it creates `/run/emubox` at 0755 if missing, writes the word to a temporary file in that directory, sets it to 0644 *before* renaming it over `/run/emubox/mode`, prints the mode it is switching to and that the current session is about to end, runs `systemctl reset-failed display-manager.service` as a best-effort step whose failure cannot end the command under `set -e`, and immediately hands over `systemctl restart --no-block display-manager.service`. The flag write and the hand-off are each guarded rather than left to `set -e`: a failed write says the selection is unchanged, and a failed hand-off says the mode was recorded and the session was not restarted. Exit zero reports only that the mode was recorded and the restart accepted. Verify by evaluating the host configuration and asserting the package is on the system path under that name, and that `services.displayManager.autoLogin.enable` is true with `user = "player"` on the normal system and forced false in the `recovery` specialisation, which are the two shapes the automatic-login check has to tell apart; behaviour is proven by task 1.7 and group 3

Behaviour is proven by tasks 3.2, 3.3 and 3.8
