## Why

The box boots to a login prompt today: `modules/kiosk` declares SDDM autologin and a session script whose body is three `TODO(design N)` comments around an `es-de` launch line, and nothing configures ES-DE, so the frontend the vendored-packages change made buildable has never run as the appliance intends. This change is the epic every later one stands on: `emubox-prepare` (the "assert the keys the flake owns, leave the rest" config editor that E4 to E8 extend), the session loop with its crash handling, the frontend's kiosk configuration, and the VM test that can finally see a graphical session. Two facts found while designing it shape the scope: ES-DE hides its entire quit menu in kiosk mode, so "power off from the frontend" needs a patch to the vendored build, and disko's install test boots its VM with a fixed 1 GB and no memory knob, so the graphical assertions need a second, plain test node.

## What Changes

- **Session loop made real.** The `emubox` SDDM session exports `ESDE_APPDATA_DIR=/data/es-de` once, then loops over `emubox-prepare` followed by `cage -- es-de`, both reading that one variable. A run shorter than 60 s counts as a crash; after three consecutive crashes the script exits and, because SDDM's autologin is configured for the first start only (`relogin = false`, replacing the earlier plan's `relogin = true`, which would have logged `player` straight back in the moment the script gave up), SDDM shows its greeter for the rest of the boot instead of relaunching forever. A reboot starts fresh. The mode flag read from `/run/emubox/mode` stays (its writer is E9).
- **`emubox-prepare`**, a Python program built by the flake: before every launch of the frontend, each relaunch included, it creates or asserts the ES-DE settings the flake owns (kiosk UI mode, the unlock sequence, ROM and media directories under `/data`, the bundled `linear-es-de` theme, `en_US`, the quit menu on) and leaves every other key as ES-DE last wrote it; it installs the flake's custom-systems file (`emubox.kiosk.customSystems`, empty until E4) or removes a stale one. Its editors for ES-DE's XML, INI files and RetroArch's flat config are unit-tested at build time, linted with ruff and type-checked with ty, and those checks run on every system `nix flake check` is invoked on, the Mac included. `nix fmt` formats Python as well as Nix.
- **ES-DE patched for kiosk-mode power off.** The vendored `es-de` gains a patch that shows the QUIT entry in kiosk mode and, within that menu in kiosk mode, offers only Reboot and Power off (the behaviour RetroPie's EmulationStation gives kiosk mode); "Quit ES-DE" and Suspend stay hidden there because the loop would relaunch the one and the box refuses the other. The existing polkit rule already lets `player` power off and reboot through logind.
- **A second VM test, `checks.x86_64-linux.kiosk`**: the host modules booted as a plain NixOS test node (no disko layout, no boot loader, 2 GB, a virtio GPU) that asserts the display manager is up, `player` has an active seat session, ES-DE is running under cage within the test's own startup budget, the settings file carries the asserted keys including the passkey, the custom systems file matches the definition and its removal branch clears it, a killed ES-DE is relaunched, three fast kills leave no ES-DE with the display manager still serving a login, and a reboot returns to the frontend. The existing install test is unchanged and keeps SDDM off. This node is where E4 to E9 add their session-level assertions.
- Module options `emubox.kiosk.passkey` (the ES-DE unlock sequence, ES-DE's own default unless the host overrides it) and `emubox.kiosk.customSystems`. README gains a kiosk section; `just kiosk-test` joins the recipes.
- The only thing that leaves is a cache entry, not a behaviour: narrowing the unfree-core selection to redistributable cores drops any such core from the public cache, and a consumer without it compiles that core instead. The box's closure is unchanged either way, and the likely count today is zero. Nothing else is removed. Emulator configuration, `es_systems.xml` content, save redirection, controllers and mode switching stay with E4 to E9. Boot time, the TV's native mode and the patched menu on the real TV are E12 bring-up lines.

## Capabilities

### New Capabilities
- `kiosk`: what the box shows and does from power-on to the frontend: the autologin session, the loop and its crash handling with the greeter as the failure state, the frontend's kiosk configuration and where its data lives, the settings the flake owns versus the ones it leaves alone, custom systems, and power off and reboot from the frontend.

### Modified Capabilities
- `packages`: ES-DE's requirement gains the kiosk-mode quit-menu patch (a build in which the patch no longer applies fails; the menu shows power off and reboot in kiosk mode), the licence guard on what reaches the public cache widens from the vendored paths to every path pushed whatever its kind, with each path's posture recorded where it is defined, and a new requirement widens the capability past vendoring: `emubox-prepare` is a program this project writes rather than vendors, and the new requirement states what the flake owes such a program - the requirement is where that list lives, not here. The capability's Purpose, which today names only what the pinned nixpkgs stopped carrying, is reworded on this branch to cover what the flake builds and caches whether vendored or its own.
- `vm-test`: two new requirements and one modified. The new ones are that a second test boots the host modules as a plain node with a graphical stack and proves the kiosk session, and that the config editor is proven without a VM, its unit tests, lint and type check running under `nix flake check` on every system the flake is checked on, the admin's Mac included. The modified one is "The test runs in CI and locally", generalised from the single install test to every VM test the flake defines, so that enrolment in `nix flake check` is stated once rather than by each test. The install test's own requirements are otherwise unchanged.

## Impact

- `modules/kiosk/default.nix` (session script rewritten, `relogin = false`, the two options, prepare wired in), `pkgs/emubox-prepare/` (new: the program, its tests, ruff config, package), `pkgs/es-de/` (new patch and its header note), `pkgs/default.nix` (one more `callPackage`, which also exposes `packages.x86_64-linux.emubox-prepare` and enrols it in the `cache-roots` linkFarm CI pushes to Cachix), `flake.nix` (the devShell gains `python3`, `ruff`, `ty` and `pytest`; the unfree-core selection feeding `cache-roots` narrowed to redistributable cores; `checks.x86_64-linux.kiosk`; `checks.<system>.emubox-prepare` for every system; the formatter gains ruff), `tests/kiosk.nix` (new), `LICENSE` (new: the repo has carried none, so the project's own programs on the public cache reach consumers with no grant), `tests/default.nix` (header comment, which no longer holds once the graphical session is proven in CI), `justfile` (`kiosk-test`, `session-check`, `just eval` gaining the kiosk and session `drvPath`s, and the `cache-push` description), `README.md`, and the comments task 5.4 sweeps in `.github/workflows/ci.yml`, `modules/facts.nix`, `modules/hardware/default.nix`, `modules/persistence/default.nix`, `overlays/default.nix`, `secrets/README.md` and `tests/values.nix` (the last three because the kiosk node consumes the same test fixture, so prose naming one test for it is as false as prose naming one test for the flake), `.gitignore` (the Python tooling's caches), none of which describe what the flake builds and caches accurately once `emubox-prepare` is in `pkgs/`, `openspec/specs/vm-test/spec.md` and `openspec/specs/packages/spec.md` (both Purposes reworded on this branch; the requirements reach them through the deltas at archive).
- No new flake inputs. `ruff`, `ty` and `python3` come from the pinned nixpkgs. The kiosk check adds one VM boot to CI, in parallel with the install test.
- `ACCT`: none.
- Depends on the base layer (persistence, `player`, `/data`) and the vendored packages (ES-DE); both are on `main`. E4 (emulators), E6 (controllers), E8 (library) and E9 (recovery) depend on this change.
