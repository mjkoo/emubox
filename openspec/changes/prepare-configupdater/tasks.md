## 1. The dependency and the shared load/dump helpers

- [ ] 1.1 Add `configupdater` to the `python3.withPackages` closure in `pkgs/emubox-prepare/package.nix`, beside `cryptography`; `nix build .#checks.aarch64-darwin.emubox-prepare` builds and its 186 existing tests still pass.
- [ ] 1.2 Add the load helper (text to document, wrapping in the synthetic section header) and the dump helper (document to text, stripping that header). Construct with `strict=False`, `delimiters=("=",)` and `comment_prefixes` per format - `("#", ";")` for INI, `("#",)` for RetroArch, matching `_parse_retroarch`, which does not treat `;` as a comment. `optionxform` is NOT a `ConfigUpdater` constructor argument in `configupdater` 3.2 and passing it raises `TypeError`; it is assigned as `str` on the constructed instance, with whatever suppression `ty check` needs so task 5.1's clean-check requirement is reachable. Do not pass `space_around_delimiters`: design decision 4 records the ruling that delimiter spacing is outside the contract, so the default stands. Tests prove a file already beginning with a section header round-trips byte-identically with no residual blank line, and that a file whose first assignment sits above every header round-trips byte-identically too - an unedited round trip is free and worth pinning, even though an *edited* file promises only that no unowned setting changed.
- [ ] 1.3 Implement design decision 7's six exclusion rules in the load helper, each with its own test.
  - Rule 1, the unterminated last line: source text that does not end in a newline gets one before wrapping, so appending an owned key to such a file cannot concatenate the two. The test drives `[A]\nToken = x` with no trailing newline, appends a missing owned key, and asserts `Token = x` survives intact on its own line - it fails against a helper without the rule, producing `Token = xNew = y`. Append only; do not implement this as strip-then-append, which would destroy the trailing blank-line run.
  - Rule 2, the indented line: the load helper strips leading whitespace from every line before wrapping, so `configparser`'s continuation handling can never swallow one. Three tests, each of which fails against a helper without the rule because the line disappears entirely: `[A]\nkey = 1\n  # note\nz = 3\n` keeps `# note` as a comment line and `z` still holds `3`; `[A]\nkey = 1\n  ind = 9\nz = 3\n` keeps `ind` as a setting holding `9`; `[A]\nkey = 1\n  [B]\nz = 3\n` puts `z` under section `B`, which is what today's `_INI_SECTION_RE` already does since it is anchored `^\s*\[`. Each test changes an owned value in the same run, since that is when an unstripped helper destroys the line. Keep a backstop assertion that no parsed option's value contains a newline, reporting the file unparseable if one does; with stripping it should be unreachable.
  - Rule 3, the bracketed line the library names differently: implement design decision 7 rule 3's three-way decision on every line whose stripped form begins with `[`. Where `SECTCRE` does not match, pass the line through; where `SECTCRE` matches and `_INI_SECTION_RE` does not, refuse; where both match but their names differ, rewrite the line to `[<name>]` before wrapping. A guard that refuses every bracketed line, or that tests `_INI_SECTION_RE` membership alone, is what these tests exist to rule out - the membership-only version passed `[Achievements] ; was [Cheevos]` while the library named that section `Achievements] ; was [Cheevos`, and the refuse-everything version destroyed files the current program preserves. Fixtures, each carrying an owned `Token` valued `REMOVE`: `[Achievements] ; was [Cheevos]` and `[Achievements] # old [name]` are normalised, the file is edited in place, the token is gone AND an unowned `UserPref = keepme` elsewhere in the file survives - these two fail against both defective versions and are the discriminating pair; `[Achievements] [was Cheevos]` and `[Achievements][x]` are refused and recreated with the token gone, matching today; `[]` and `[] ; c` reach the parser, raise `ParsingError` and recreate with the token gone, where today the token strands; `[foo bar = baz` is passed through and survives as an unowned option, where a refuse-everything guard would destroy the file; `[foo] = bar` is refused and recreated, which task 2.5 records as a shape that moves. Assert `[Achievements]` and `[A] ; plain comment` are still edited in place untouched. For RetroArch, a `[Foo]` line above a `cheevos_token` assignment and `[something] = "x"` both recreate. This is the credential path.
  - Rule 4, the sentinel collision: the helper refuses a document in which any line, as it stands after rule 2's whitespace stripping and rule 3's header normalisation, is matched by `configupdater`'s `SECTCRE` with a header group equal to the sentinel, with no restriction on what follows the closing bracket - the group is `(?P<raw_comment>.*)` and accepts any text. The test drives the plain, leading-whitespace, trailing-comment and arbitrary-suffix spellings (`[<sentinel>] extra`, `[<sentinel>] = 3`) for both formats, plus the spelling only the post-normalisation check catches: `[<sentinel>] ; [x]`, whose greedy `SECTCRE` header in the source text is `<sentinel>] ; [x` until rule 3's rewrite normalises it to the canonical sentinel line. A naive substring test for `[<sentinel>]\n`, a check tolerating only whitespace or a comment, and a check that runs over the raw source text before normalisation all fail the suite.
  - Rule 5, the empty file: text that is empty or whitespace-only is reported unparseable, and reported *silently*, so `set_ini_settings` reaches its own deferred "is empty; recreating it" note and emits it only once a write is confirmed. Noting it in the helper would reproduce the per-launch spurious notice `_parse_ini`'s comment records. INI only, matching today. The test asserts both the recreation and that the helper itself emitted nothing.
  - Rule 6, the library's parse failures: the helper catches `configparser.Error`, which `configupdater` re-exports and which covers `ParsingError` and `MissingSectionHeaderError`, and reports the file unparseable. Without it a `key: value` line, a bare key, or a bare `= value` line raises out of the editor into `main`, whose loop guards `except OSError` only, and the kiosk session runs `emubox-prepare` unguarded under `set -e` with an EXIT trap that ends at the greeter. For each shape the test asserts the editor recreates the file carrying every applicable owned value - not merely that it returned without raising, which a helper that swallows the exception and gives up would also satisfy, leaving the file without the flake's values.
- [ ] 1.4 Add tests pinning the two library behaviours design decisions 3 and 5 name. For decision 3, assert the behaviour that actually differs, which is lookup and not rendering: with the helper in place `"Username" in section` is True for a file spelling the key `Username`, `section["Username"]` and `section["username"]` resolve to distinct options holding distinct values, and `section.options()` returns both spellings unfolded. All three fail against a helper built with the library's default `optionxform`, whereas a written key's declared case is preserved by `configupdater` either way and therefore pins nothing - do not use it as the criterion. This matters because with the default, `"Username" in section` is False while `section["Username"]` resolves to the `username` option, so an iterate-to-absence loop written as `while key in section` never runs and the editor appends a second credential beside the stale one. For decision 5, assert that a single `del section[key]` on a section carrying that key twice demonstrably leaves the second, so iterating to absence is what the editors must do.
- [ ] 1.5 Add a test asserting no file this program writes ever contains the synthetic header sentinel, parameterised over every format and every writing branch (fresh, edited, recreated, all-removals), including a fixture whose input already contains the sentinel and therefore takes rule 4's recreate path, and a fixture spelling the sentinel with a trailing comment that contains a `]` (`[<sentinel>] ; [x]`), which reaches rule 4's refusal only after rule 3's rewrite normalises it.

## 2. The sectioned-INI editor

- [ ] 2.1 Move `set_ini_settings` onto the load/dump helpers, keeping its signature, its `REMOVE` handling, the `_holds_something` guard, the "no owned keys means leave the file alone" rule and every journal note - including the deferred "is empty; recreating it" note, which now depends on design decision 7's rule 5 rather than on `_parse_ini`'s own emptiness check, and which `test_ini_an_empty_file_owning_a_real_value_still_notes_the_recreation` and `test_ini_an_empty_file_owning_only_a_removal_writes_and_notes_nothing` pin. The recreate branch moves too: `_render_ini` is deleted in task 4.1, so a recreated file is built as a document and serialised through the dump helper, wrapped in the sentinel exactly as a loaded document is, so a single unconditional strip-the-first-line dump path serves both loading and recreation. Verified that this changes no bytes - programmatic `add_section` plus assignment renders `[A]\nk = v\n[B]\nj = w\n`, identical to `_render_ini`'s output - so the existing recreation tests pass unedited. Every existing INI test that asserts a key, a value or a journal note passes unedited. A test that fails only because formatting moved - delimiter spacing on a changed owned line, the position of a seeded key relative to a trailing comment or blank line - is amended, citing the contract, since design decision 7 puts formatting outside it; `test_ini_appends_a_key_before_a_trailing_comment` is the one existing test in that class. A test that fails because a key or a value changed is a finding to report, not a test to amend.
- [ ] 2.2 Assign a value only when the parsed value differs from the flake's. This is the flash-write guard, not a formatting one: Azahar rewrites `qt-config.ini` in full whenever it saves, so an unconditional assignment would mean one extra write to flash before every launch, forever. The fixture is the shape of Azahar's `qt-config.ini` - the one genuinely QSettings-written file among the eight ini targets, spaceless assignments and a `fullscreen\default` key included. Add a second fixture in the shape of `scummvm.ini`, the other spaceless writer. The test runs the editor twice with the value the file already holds and asserts the file is unwritten (`freeze`/`unwritten`).
- [ ] 2.3 Reduce a repeated owned key to exactly one assignment in all three shapes a repeat takes: across every instance of its section (via `iter_sections()`), across the headerless region and its section, and - the shape the current editor does not handle - twice inside ONE section instance. Verified against today's code: a section holding `Username = stale-one` then `Username = stale-two`, with an owned write of `correct`, comes back as `Username = correct` followed by `Username = stale-two`, because the write pass sweeps with the whole section instance protected. The mechanism is design decision 5's write-side rule, which is iterate-to-*one* rather than iterate-to-absence: absence in every section instance except the one being written and in the headerless region, and inside the written instance delete down to a single survivor and then apply task 2.2's compare-before-assign to it. Iterating to absence there would delete the survivor as well, and the naive repair of deleting all then assigning writes the file on every launch, which task 2.2's flash-write guard and this task's own "a second run is unwritten" both forbid. a single `section[key] = value` against `configupdater` 3.2 with `strict=False` edits the first line and leaves the second, exactly as a single `del` does. Where the surviving assignment ends up in the section is outside the contract and is not asserted. The three INI duplicate-write tests the preceding fix added - `test_ini_write_leaves_no_stale_twin_in_a_duplicated_section`, `test_ini_write_sweeps_a_stray_assignment_above_every_section_header` and `test_ini_write_is_idempotent_after_collapsing_a_duplicate` - pass unedited. Add the tests none of them supplies: an owned key assigned twice inside one section instance ends as exactly one assignment holding the flake's value, and a second run is unwritten; and an owned key assigned in the headerless preamble while its section is absent from the file entirely ends as exactly one assignment under the freshly appended section, with a second run unwritten - verified against today's code, which appends the section but leaves the preamble twin standing because the stale-twin sweep stops when the section has no bounds yet, so the emulator reads the stale value for one launch and the next run writes again. This is the "repeated line" form the delta spec scenario "Owned key is assigned more than once" names, and the RetroAchievements `Username` and `Token` keys are where a surviving stale copy is a bearer credential rather than a preference.
- [ ] 2.4 Keep a key of the same name under a section the flake does not own untouched, and keep every assignment of an unowned key. `test_ini_write_leaves_no_stale_twin_in_a_duplicated_section` and `test_ini_removal_still_reports_no_write_when_only_other_sections_match` pass unedited. Those pin owned-key and cross-section behaviour, not repeats of an unowned key, and the delta spec's "A key the flake does not own SHALL keep every one of its assignments" has no flat-file test today - the only unowned-repeat test in the suite is `test_esde_write_leaves_a_repeated_unowned_element_alone`, for the editor this change does not touch. Add one: an INI fixture whose unowned key appears twice inside one section and once under a second, unowned section, asserting all three assignments and their values survive a write that changes an owned key elsewhere in the file. Losing one of them is a setting disappearing, which the contract does not permit.
- [ ] 2.5 Assert each shape's recreate outcome against the mechanism that delivers it, rather than asserting parity in the abstract. A line that is not an assignment still triggers recreation. A `key: value` line still triggers it, which is what `delimiters=("=",)` plus rule 6's `configparser.Error` catch buys, since the library's default delimiters would make it an ordinary option. No indented line triggers it at all - neither a comment, nor an assignment, nor a section header - because rule 2 strips leading whitespace before the library can read any of them as a value continuation; assert each of the three survives an owned-value change rather than asserting a recreate. A bracketed line the library would read as a header under a name `_INI_SECTION_RE` does not give it triggers it, which is rule 3. An empty or whitespace-only file triggers it and still carries its own "is empty; recreating it" note, which is rule 5 and is pinned by the two existing empty-file tests. A file that is merely awkward - duplicate section header, headerless preamble - still does not. Record both shapes design decision 7 accepts as moving toward recreation, and assert each against the mechanism that delivers it: a bare `= value` line recreates via rule 6, because the library cannot parse the file at all; and a line beginning with `[` that carries an `=` after the closing bracket, such as `[foo] = bar`, recreates via rule 3, where today `_split_ini_assignment` preserves it as an assignment with key `[foo]`. For the second, assert the recreate outcome rather than assuming it, since the alternative the rule prevents is the library reading it as a header and reattributing every key below it. Survey ScummVM's `scummvm.ini` against a file ScummVM itself wrote, which its package supports on the administrator's machine, and confirm it presents no awkward shape beyond the duplicate section header and headerless preamble. Do NOT gate on the same survey for PPSSPP: `nixpkgs#ppsspp.meta.platforms` is Linux-only and the CI VM test is the only place that emulator runs, so settle it by reading `IniFile::Save` at the locked revision instead, per design decision 1.
- [ ] 2.6 Pin the contract through the mutate-and-serialise path, which nothing pins today. Within an LF file: change one owned value, and separately append a missing owned key, and assert in each case that every key the flake does not own is still present with its value unchanged, that a repeated unowned key keeps every one of its assignments, and that no setting has moved from one section to another. Do NOT assert delimiter spacing, line position, comment survival or byte identity of the remainder: design decision 7 puts all four outside the contract, and asserting them would pin a property the ruling deliberately declines to buy. Do NOT assert line terminators: `Path.read_text` folds CRLF to LF before and after this change. Cover the removal path too, which runs the same machinery and is where a credential comes off: with an owned key valued `REMOVE`, assert every unowned key keeps its value, every repeated unowned assignment survives, and each setting stays under its original section. Include a fixture whose last line has no trailing newline, asserting that appending an owned key leaves the previous line's key and value intact rather than concatenating onto it (rule 1). The existing preservation tests compare a few indices through `splitlines()`; this task is what makes the promise checkable at the level the contract actually states.
- [ ] 2.7 Move `_current_ini_value` onto the same load helper, through the quiet variant design decision 6 describes: it stays silent on a missing, unreadable or unparseable file, because it runs before this run has decided to write anything and a journal note there would announce a recreation that is not happening. It gains the fifth `None` answer decision 6 enumerates - "file unparseable" - because the shared helper validates where `_read_quietly` did not; that reads as "the token changed" and rewrites `login_timestamp` once, which is correct on a file about to be recreated anyway. Add tests for all five `None` causes asserting no journal output, since the two existing tests exercise only a readable file with the section and key present. `test_duckstation_login_values_writes_login_timestamp_when_the_token_changes` and `test_duckstation_login_values_omits_login_timestamp_when_the_token_is_unchanged` pass unedited. Without this task the deletions in task 4.1 strand it: it calls `_lines`, `_ini_section_bounds`, `_ini_key_index` and `_split_ini_assignment`, and its only caller, `duckstation_login_values`, is reached from `apply_retroachievements` for every duckstation target declaring a `login_timestamp` key.

## 3. The RetroArch editor

- [ ] 3.1 Move `set_retroarch_settings` onto the same helpers, reading its headerless file through the synthetic header and rendering values in RetroArch's `key = "value"` form, including on the recreate branch, since `_render_retroarch` is deleted in task 4.1. Rule 3's RetroArch half - refuse any document containing a section other than the synthetic one - is what keeps this editor's premise true that the whole file is one section. Every existing RetroArch test that asserts a key, a value or a note passes unedited; no existing RetroArch fixture carries a bracket line or a spaceless assignment, so none is in the amended-for-formatting class. Task 3.4 carries this editor's contract obligation.
- [ ] 3.2 Reduce a repeated owned key to one assignment in the flat file, by the same iterate-to-*one* rule as task 2.3, never iterate-to-absence: inside the single synthetic section delete down to one surviving assignment, then apply task 3.3's compare-before-assign to that survivor. `REMOVE` is the only path in this editor that iterates to absence. This matters more here than in the INI editor: the whole file is one section, so there is no other instance and no separate headerless region, and iterating to absence would delete every owned assignment and append each one back - leaving the bytes identical but the change flag set, so `retroarch.cfg` is written to flash before every launch, forever. Under rule 3 the whole file is one synthetic section or it is recreated, so the within-one-section repeat is this editor's only repeat shape; `test_retroarch_write_leaves_no_stale_twin` and `test_retroarch_removal_sweeps_every_occurrence` pass unedited.
- [ ] 3.3 Assign only on a genuine value difference, matching task 2.2, proven by the same freeze/unwritten shape against a RetroArch fixture.
- [ ] 3.4 The contract obligation of task 2.6, against a RetroArch fixture: change one owned value and separately append a missing owned key, asserting every unowned key keeps its value, a repeated unowned key keeps every assignment, and nothing is reattributed. Cover the removal path as in task 2.6. The same exclusions apply - no assertions on spacing, position, comments, byte identity or line terminators - and the same unterminated-last-line fixture. Also assert this editor's format-specific comment handling, which no existing test pins: a `;`-prefixed line carrying no `=` is not a comment in a RetroArch file (`comment_prefixes=("#",)`, matching `_parse_retroarch`) and so is a line that is not a setting, triggering recreation. Use the no-`=` spelling: `;key = "v"` parses as an option named `;key`, which is what `_split_ini_assignment` does with it today, so it pins nothing.
